# Site tools

This folder isn't published (Jekyll skips folders that start with `_`).

- `build.py` writes the main pages (`index.html`, `research.html`, …) and the shared header,
  footer and head used by the writing section. Run it from the repository root after editing it:
  `python3 _tools/build.py`. Its docstring explains the details.
- `writing-post-template.md` is a commented template for new writing posts.

## The writing section

AI research notes: write-ups of papers, small reproductions and experiments, each linked to its
code. Posts live in `_writing/` and are published at `/writing/<slug>/`. They're a Jekyll
*collection*, not `_posts`, so they never appear in the old Word cluster blog at `/blog`.

| Piece | Where |
|---|---|
| Posts | `_writing/YYYY-MM-DD-slug.md` |
| Images | `images/writing/<slug>/` |
| Post layout | `_layouts/writing-post.html` (on top of `_layouts/writing-default.html`) |
| Index page | `writing/index.html` with `_layouts/writing-index.html` |
| Atom feed | `writing/feed.xml` (served at `/writing/feed.xml`) |
| Styles | the "Writing section" block at the end of `style.css` |
| Header, footer, nav | generated by `build.py` into `_includes/site-*.html` |
| Section name and URL | `WRITING_LABEL` and `WRITING_URL` in `build.py` |
| Collection settings | `collections:` and `defaults:` at the end of `_config.yml` |

### How to write a post

1. Copy the template and give it a date and a slug:
   ```sh
   cp _tools/writing-post-template.md _writing/2026-11-10-llm-judges.md
   ```
2. Fill in the front matter and write the post in plain Markdown. Keep `published: false`
   while drafting.
3. Put any images in `images/writing/llm-judges/` and link them as
   `![alt text](/images/writing/llm-judges/chart.png "Caption")`.
4. Preview it locally (see below), including drafts.
5. To publish, delete the `published: false` line (or set it to `true`), commit, and open a pull
   request. The post goes live when it's merged into `main`.

### Preview locally

You need Ruby 3 and Bundler. The first time, install the same gems GitHub Pages uses:

```sh
bundle install
```

Then, from the repository root:

```sh
bundle exec jekyll serve --unpublished
```

and open http://localhost:4000/writing/. `--unpublished` also shows posts with
`published: false`; leave it out to see exactly what will go live. The server rebuilds when you
save a file. If you change `build.py`, run `python3 _tools/build.py` first.

### Things to know

- **Drafts:** posts with `published: false` are never built on the live site, so they don't
  appear on `/writing/`, in the feed, or at their URL. They're still in the public GitHub
  repository, though, so anyone browsing the repo can read them.
- **Math:** set `math: true` to load KaTeX on that post. Use `$…$` inline and `$$…$$` on their own
  lines for display. Inside single dollars, write `\cdot` or `\ast` instead of `*`, and
  `\lbrace … \rbrace` instead of `\{ … \}`; Markdown otherwise eats those characters. In a
  post with `math: true`, write money as "USD 5" rather than with a dollar sign, because two dollar
  signs in one paragraph are read as math. Posts without `math: true` can use `$` freely.
- **Curly braces:** Jekyll reads `{{` and `{%` in a post as template tags, even inside code blocks.
  If a post needs them (Jinja or Go templates, say), put a space between the braces where you can,
  or ask for help: the Jekyll-only fix (`{% raw %}`) would make the post less portable.
- **Dates in the future:** a post dated after the day the site was last built doesn't appear
  until the next build. GitHub Pages only rebuilds when something is pushed, so date posts today
  or earlier. Use `bundle exec jekyll serve --unpublished --future` to preview future-dated ones.
- **Reading time** is computed from the word count at 200 words per minute.
- **Next/previous links:** each post links to the next newer post, or to the previous one if it's
  the newest.

## Migrating later

The posts are designed to move to another engine (Hugo, Astro, Quarto, another Jekyll theme) with
almost no edits. They're plain Markdown with front matter; all presentation is in the layouts.

### Front-matter fields

| Field | Required | Meaning |
|---|---|---|
| `title` | yes | Post title |
| `date` | yes | Publication date (`YYYY-MM-DD`); sets the order, newest first |
| `summary` | no | One or two sentences for the index, the feed and the meta description |
| `tags` | no | List of short lowercase tags |
| `paper` | no | URL of the paper the post is about, shown as a "paper" link |
| `code` | no | URL of the code, shown as a "code" link |
| `status` | no | Epistemic status: how confident the post is, shown as a callout above it |
| `math` | no | `true` if the post has math, to load KaTeX |
| `published` | no | `false` for drafts; anything else (or no field) publishes it |
| `original_url` | no | For a post first published elsewhere: its original URL. Shows an "Originally published on …" note and makes the original the canonical URL, so search engines don't treat the copy as a duplicate |
| `original_site` | no | Name of the site in that note (for example `Word cluster`) |

### Conventions to keep

- **URLs:** every post is at `/writing/<slug>/`, where `<slug>` is the file name without the date
  and `.md` (`_writing/2026-11-10-llm-judges.md` → `/writing/llm-judges/`). The index is at
  `/writing/`. Keep these URLs, or add redirects from them, so links in CVs and elsewhere keep
  working.
- **Feed:** `/writing/feed.xml` (Atom). Keep it at the same URL so subscribers don't lose it.
- **Images:** `images/writing/<slug>/`, referenced with root-relative paths
  (`/images/writing/<slug>/file.png`). Copy the folder as is.
- **Math:** standard `$…$` (inline) and `$$…$$` (display) delimiters, which KaTeX and MathJax
  setups in most engines support.
- **Captions:** a Markdown image title (`![alt](src "Caption")`) becomes a figure caption. The
  current site does that in a few lines of JavaScript in `_layouts/writing-post.html`; most other
  engines have an image "render hook" or option for the same thing.
- **Footnotes and tables** use the common Markdown syntax (`[^1]`, pipe tables).
- **Copied Word cluster posts:** the 8 posts tagged `word-cluster` are copies of the 2018 blog
  posts in `_posts/`, which stay at their original `/blog/...` URLs. Their `original_url` must
  stay the canonical URL, so keep rendering it as `<link rel="canonical">`. Unlike new posts,
  their bodies contain some inline HTML (links, `<font color>`) and images linked from GitHub
  (`github.com/.../images/blog/...?raw=true`), kept exactly as originally published.
